## BACKGROUND OF THE INVENTION

### Field of the Invention

This invention relates generally to audio signal processing systems and, more particularly, to intelligent audio effects processors that use artificial intelligence and natural language processing to generate audio effect presets from voice commands, combined with physical hardware controls for real-time parameter adjustment.

### Description of Related Art

**Problem 1: Complexity of Audio Effects**

Modern digital audio effects processors offer extensive capabilities but suffer from significant usability problems. Professional audio plugins typically have 20-50 adjustable parameters per effect. A typical music production session may use 10-20 different effects across multiple tracks, creating thousands of possible parameter combinations. This complexity creates several issues:

- **Steep Learning Curve**: New users face months of learning before effectively using professional audio tools
- **Time Consumption**: Sound designers spend hours tweaking parameters to achieve desired sounds
- **Choice Paralysis**: Musicians with limited technical knowledge struggle to translate creative intent into technical parameter adjustments
- **Workflow Disruption**: Switching between creative thinking and technical parameter manipulation disrupts artistic flow

**Problem 2: Limitations of Existing Automation**

Prior art systems have attempted to address these problems through various automation approaches:

- **Preset Libraries**: Provide pre-configured effect settings but lack customization to user intent
- **Automatic Mastering Services** (e.g., LANDR): Analyze completed audio files and apply processing, but operate on finished material rather than enabling creative exploration
- **AI-Powered Mixing Tools** (e.g., iZotope): Analyze audio characteristics to suggest processing, but require audio input and don't support creative ideation
- **Template-Based Systems**: Offer starting points but still require extensive manual adjustment

These systems share common limitations:
1. They require existing audio for analysis (reactive, not proactive)
2. They don't understand natural language creative intent
3. They lack real-time interactive control
4. They don't combine AI intelligence with physical hardware interfaces

**Problem 3: Interface Limitations**

Current audio effects interfaces fall into two categories:

**Software Interfaces:**
- Mouse and keyboard control (slow, non-tactile)
- Screen-based interaction (disrupts musical flow)
- Computer-dependent (not suitable for live performance)

**Hardware Interfaces:**
- Fixed function per control (limited flexibility)
- No intelligent parameter selection
- Manual preset creation and management
- No voice control integration

No prior art system combines natural language understanding, intelligent preset generation, physical hardware control, and real-time performance optimization in a single integrated system.

**Problem 4: Gap in Voice-Controlled Audio**

While voice assistants (Siri, Alexa, Google Assistant) have become ubiquitous for general device control, the professional audio domain lacks voice control systems that:
- Understand creative and technical audio terminology
- Generate complete effect configurations from descriptions
- Integrate voice with professional hardware interfaces
- Operate in real-time for musical performance

**Need for the Invention**

There is therefore a need for an audio effects system that:
1. Accepts natural language voice descriptions of desired sound characteristics
2. Automatically generates appropriate multi-effect chains with optimized parameters
3. Provides immediate tactile hardware control for real-time adjustment
4. Operates as a standalone device without requiring a computer
5. Combines AI intelligence with professional audio engineering best practices
6. Enables both studio production and live performance applications

The present invention addresses these needs through a novel combination of voice-controlled AI preset generation, multi-tier intelligent routing, three-stage parameter generation pipeline, and integrated hardware interface.

This embodiment is particularly useful for desktop plugin versions, batch preset generation, and API integration for third-party applications.

### Software Platform Embodiment

While the preferred embodiment uses Raspberry Pi 5 as embedded standalone device, the invention's architecture is platform-agnostic and can deploy in multiple configurations: (1) Desktop plugin (VST3/AU/AAX) running in digital audio workstation on macOS/Windows/Linux, (2) Cloud service with Trinity AI on server accessible via web browser or mobile app, (3) Mobile application (iOS/Android) with on-device or cloud AI. All embodiments use the same Trinity AI pipeline (Visionary → Calculator → Alchemist) and DSP engine library (57 engines, 6-slot architecture).

### Distinction from Multi-Track Semantic Mixing Systems

This invention differs fundamentally from semantic mixing systems that combine multiple audio tracks, such as Fraunhofer's Semantic Audio Track Mixer (US9532136B2). The Fraunhofer system processes a PLURALITY of audio tracks and uses semantic commands to derive mixing parameters for COMBINING those tracks into a mixture signal (examples: "mix guitar prominently" adjusts relative levels between guitar track and other tracks, "move keyboards to background" adjusts inter-track balance).

In contrast, the present invention processes a SINGLE audio track and uses semantic commands to derive EFFECTS parameters for creative audio processing. Examples include "warm reverb" (generates reverb decay time, damping, size parameters), "vintage delay" (selects tape echo engine with appropriate feedback and time settings), and "crunchy distortion" (selects distortion engine with drive and tone parameters). The invention does not combine multiple tracks—it creates multi-EFFECT chains on individual audio sources. This represents a different domain of audio engineering: creative effects processing vs. multi-track mixing/mastering.

### 2. THREE-TIER INTELLIGENT ROUTING SYSTEM

#### 2.1 System Architecture

The three-tier routing system analyzes incoming natural language requests and routes them to the appropriate processing tier based on complexity, specificity, and resource requirements.

**Tier Classification Algorithm:**

```
FUNCTION classifyRequest(userPrompt):
    // Extract keywords
    keywords = extractKeywords(userPrompt)

    // Check for specific engine names
    specificEngines = matchEngineNames(keywords)

    // Analyze complexity
    wordCount = countWords(userPrompt)
    technicalTerms = countTechnicalTerms(userPrompt)
    artisticDescriptors = countArtisticDescriptors(userPrompt)

    // Tier 1: Exact Match (Simple + Specific)
    IF (specificEngines.count == 1 OR specificEngines.count == 2) AND
       (artisticDescriptors.count == 0) AND
       (wordCount < 8):
        RETURN TIER_1_EXACT_MATCH

    // Tier 3: Full Artistic (Complex + Poetic)
    ELSE IF (specificEngines.count == 0) AND
            (artisticDescriptors.count >= 2) AND
            (wordCount >= 8):
        RETURN TIER_3_FULL_ARTISTIC

    // Tier 2: Guided Artistic (Default)
    ELSE:
        RETURN TIER_2_GUIDED_ARTISTIC

END FUNCTION
```

### 3. TRINITY AI PIPELINE

The Trinity AI pipeline consists of three specialized agents, each with a distinct role in preset generation.

#### 3.1 VISIONARY Agent (Intent Interpretation)

**Function**: Translate natural language input into technical audio semantics

**Input**:
- User natural language prompt (text string)
- Available engine library (57 engines with metadata)
- Musical context (if specified: genre, instrument, use case)

**Processing Algorithm**:

```
FUNCTION visionaryAgent(userPrompt, engineLibrary):

    // Step 1: Extract Creative Intent
    intent = extractIntent(userPrompt)
    intent.mood = analyzeMood(userPrompt)        // happy, dark, aggressive, calm
    intent.genre = detectGenre(userPrompt)        // rock, electronic, jazz, classical
    intent.instrument = detectInstrument(userPrompt)  // guitar, vocal, synth, drums
    intent.intensity = measureIntensity(userPrompt)   // subtle, moderate, extreme

    // Step 2: Extract Sonic Characteristics
    characteristics = {}
    characteristics.warmth = analyzeWarmth(userPrompt)      // -1 (cold) to +1 (warm)
    characteristics.brightness = analyzeBrightness(userPrompt)  // -1 (dark) to +1 (bright)
    characteristics.space = analyzeSpace(userPrompt)        // 0 (dry) to 1 (spacious)
    characteristics.aggression = analyzeAggression(userPrompt)  // 0 (soft) to 1 (aggressive)
    characteristics.movement = analyzeMovement(userPrompt)    // 0 (static) to 1 (dynamic)

    // Step 3: Map to Audio Terminology
    technicalTerms = mapToTechnical(intent, characteristics)
    /*
    Example mappings:
    "warm" → [tube_saturation=0.3, low_freq_boost=0.2, high_freq_cut=0.3]
    "spacious" → [reverb_size=0.8, stereo_width=0.7, delay_time=0.4]
    "aggressive" → [distortion=0.6, compression_ratio=0.7, high_freq_boost=0.4]
    */

    // Step 4: Select Candidate Engines
    candidateEngines = selectEngines(technicalTerms, engineLibrary)

    // Step 5: Score and Rank
    FOR EACH engine IN candidateEngines:
        score = 0.0

        // Musical relevance (30%)
        IF engine.categories MATCHES intent.genre:
            score += 0.3

        // Characteristic match (40%)
        characterMatch = compareCharacteristics(engine.profile, characteristics)
        score += 0.4 * characterMatch

        // Technical appropriateness (30%)
        IF engine.type IN technicalTerms.engineTypes:
            score += 0.3

        engine.score = score

    // Step 6: Select Top Engines
    selectedEngines = getTopN(candidateEngines, count=4 to 6)

    // Step 7: Generate Preset Name
    presetName = generateName(intent, selectedEngines)
    // Examples: "Warm Vocal Reverb", "Aggressive Metal Guitar", "Spacious Ambient Pad"

    RETURN {
        engines: selectedEngines,
        characteristics: characteristics,
        intent: intent,
        presetName: presetName,
        confidence: averageScore(selectedEngines)
    }

END FUNCTION
```

#### 3.2 CALCULATOR Agent (Parameter Prediction)

**Function**: Generate specific numerical parameter values for selected engines

**Input**:
- Selected engines from VISIONARY
- Sonic characteristics (warmth, brightness, space, aggression, movement)
- Musical context (genre, instrument, use case)

**Processing Algorithm**:

```
FUNCTION calculatorAgent(visionaryOutput):

    preset = {}

    FOR EACH engine IN visionaryOutput.engines:

        // Step 1: Load Default Parameters
        parameters = loadDefaults(engine.id)

        // Step 2: Apply Characteristic-Based Nudging
        characteristics = visionaryOutput.characteristics

        // Warmth Adjustments
        IF characteristics.warmth > 0.5:
            IF engine.hasParameter("tube_drive"):
                parameters.tube_drive += 0.1 * characteristics.warmth
            IF engine.hasParameter("low_freq"):
                parameters.low_freq += 0.15 * characteristics.warmth
            IF engine.hasParameter("high_freq"):
                parameters.high_freq -= 0.1 * characteristics.warmth

        // Brightness Adjustments
        IF characteristics.brightness > 0.5:
            IF engine.hasParameter("high_freq"):
                parameters.high_freq += 0.15 * characteristics.brightness
            IF engine.hasParameter("presence"):
                parameters.presence += 0.1 * characteristics.brightness

        // Space Adjustments
        IF characteristics.space > 0.5:
            IF engine.hasParameter("reverb_size"):
                parameters.reverb_size = 0.5 + (0.5 * characteristics.space)
            IF engine.hasParameter("stereo_width"):
                parameters.stereo_width += 0.2 * characteristics.space
            IF engine.hasParameter("delay_time"):
                parameters.delay_time += 0.3 * characteristics.space

        // Aggression Adjustments
        IF characteristics.aggression > 0.5:
            IF engine.hasParameter("distortion"):
                parameters.distortion += 0.3 * characteristics.aggression
            IF engine.hasParameter("compression_ratio"):
                parameters.compression_ratio += 0.2 * characteristics.aggression
            IF engine.hasParameter("attack"):
                parameters.attack -= 0.2 * characteristics.aggression  // Faster attack

        // Step 3: Genre-Specific Optimization
        genre = visionaryOutput.intent.genre

        IF genre == "metal":
            IF engine.type == "distortion":
                parameters.drive = MAX(parameters.drive, 0.7)
            IF engine.type == "compression":
                parameters.ratio = MAX(parameters.ratio, 0.6)

        IF genre == "jazz":
            IF engine.type == "reverb":
                parameters.size = MIN(parameters.size, 0.6)  // Tighter reverb
            IF engine.type == "compression":
                parameters.ratio = MIN(parameters.ratio, 0.4)  // Gentle compression

        // Step 4: Instrument-Specific Optimization
        instrument = visionaryOutput.intent.instrument

        IF instrument == "vocal":
            IF engine.type == "eq":
                parameters.freq_200hz -= 0.1  // Reduce mud
                parameters.freq_3khz += 0.15  // Presence boost
            IF engine.type == "compression":
                parameters.attack = 0.3  // Medium attack
                parameters.release = 0.4  // Medium-fast release

        IF instrument == "guitar":
            IF engine.type == "eq":
                parameters.freq_80hz -= 0.2   // High-pass
                parameters.freq_2khz += 0.1   // Bite

        // Step 5: Professional Gain Staging
        parameters = applyGainStaging(parameters, engine)

        // Step 6: Musical Time Subdivision
        IF engine.hasParameter("delay_time") OR engine.hasParameter("reverb_decay"):
            parameters = applyMusicalTiming(parameters, tempo=120)  // Default 120 BPM

        // Step 7: Store in Preset
        preset.addEngine(engine.id, parameters)

    RETURN preset

END FUNCTION
```

**Gain Staging Algorithm**:

```
FUNCTION applyGainStaging(parameters, engine):

    // Ensure output doesn't exceed unity gain
    IF engine.hasParameter("output_gain"):
        totalGain = calculateTotalGain(parameters)
        IF totalGain > 1.5:  // 150% = +3.5 dB
            parameters.output_gain = 1.0 / totalGain

    // Prevent clipping from distortion
    IF engine.type == "distortion":
        IF parameters.drive > 0.7:
            parameters.output_level = 0.8  // Compensate for drive increase

    // Balance EQ boosts with cuts
    IF engine.type == "eq":
        totalBoost = sum(parameters.gains WHERE gain > 0)
        IF totalBoost > 0.5:  // More than +3 dB total boost
            parameters.master_gain = 1.0 - (0.3 * totalBoost)

    RETURN parameters

END FUNCTION
```

FUNCTION applyMusicalTiming(parameters, tempo):

    beatDuration = 60.0 / tempo  // seconds per beat

    IF parameters.hasParameter("delay_time"):
        // Convert normalized [0-1] to musical subdivisions
        normalized = parameters.delay_time

        IF normalized < 0.25:
            subdivision = "sixteenth"  // 1/16 note
            parameters.delay_time_ms = beatDuration * 0.25 * 1000
        ELSE IF normalized < 0.5:
            subdivision = "eighth"     // 1/8 note
            parameters.delay_time_ms = beatDuration * 0.5 * 1000
        ELSE IF normalized < 0.75:
            subdivision = "quarter"    // 1/4 note
            parameters.delay_time_ms = beatDuration * 1000
        ELSE:
            subdivision = "half"       // 1/2 note
            parameters.delay_time_ms = beatDuration * 2 * 1000

    RETURN parameters

END FUNCTION

#### 3.3 ALCHEMIST Agent (Validation & Optimization)

**Function**: Validate parameters, optimize signal chain, enforce safety rules

**Input**:

**Processing Algorithm**:

```
FUNCTION alchemistAgent(calculatorPreset):

    // Step 1: Parameter Validation and Clamping
    FOR EACH slot IN calculatorPreset.slots:
        FOR EACH parameter IN slot.parameters:
            // Ensure all values in safe range [0.0, 1.0]
            parameter.value = CLAMP(parameter.value, 0.0, 1.0)

            // Special safety checks
            IF parameter.name == "feedback":
                parameter.value = MIN(parameter.value, 0.85)  // Prevent runaway feedback

            IF parameter.name == "resonance":
                parameter.value = MIN(parameter.value, 0.90)  // Prevent self-oscillation

            IF parameter.name == "distortion" OR parameter.name == "drive":
                // Ensure compensating output reduction
                IF parameter.value > 0.7:
                    slot.parameters.output_level = 0.8

    // Step 2: Signal Chain Optimization
    optimizedPreset = optimizeSignalChain(calculatorPreset)

    // Step 3: Gain Staging Verification
    totalGain = calculateChainGain(optimizedPreset)
    IF totalGain > 1.5:  // +3.5 dB
        // Reduce output level of last effect in chain
        lastSlot = optimizedPreset.getLastActiveSlot()
        lastSlot.parameters.output_level *= (1.5 / totalGain)

    // Step 4: Prevent Dangerous Combinations
    IF hasFeedbackRisk(optimizedPreset):
        reduceFeedbackParameters(optimizedPreset)

    IF hasPhaseIssues(optimizedPreset):
        adjustPhaseRelationships(optimizedPreset)

    // Step 5: Format for Deployment
    finalPreset = formatPreset(optimizedPreset)

    RETURN finalPreset

END FUNCTION
```

**Signal Chain Optimization Algorithm**:

```
FUNCTION optimizeSignalChain(preset):

    // Define optimal signal flow order
    ORDER = [
        "dynamics",      // Compressors, gates, limiters
        "filter",        // EQ, filters
        "distortion",    // Saturation, distortion, overdrive
        "modulation",    // Chorus, flanger, phaser
        "pitch",         // Pitch shifters, harmonizers
        "delay",         // Delay, echo
        "reverb",        // Reverbs
        "spatial",       // Stereo imaging, panning
        "utility"        // Gain, DC filter
    ]

    // Extract active engines
    activeEngines = []
    FOR EACH slot IN preset.slots:
        IF slot.active:
            activeEngines.add(slot.engine)

    // Sort by optimal order
    sortedEngines = []
    FOR EACH category IN ORDER:
        FOR EACH engine IN activeEngines:
            IF engine.category == category:
                sortedEngines.add(engine)

    // Rebuild preset with optimized order
    optimizedPreset = {}
    slotIndex = 0
    FOR EACH engine IN sortedEngines:
        optimizedPreset.slots[slotIndex] = engine
        slotIndex++

    RETURN optimizedPreset

END FUNCTION
```

**Why This Order?**

1. **Dynamics First**: Control dynamic range before other processing
   - Compression/gating creates consistent level for downstream effects
   - Prevents overloading subsequent stages

2. **EQ/Filters Second**: Shape frequency content on dynamically controlled signal
   - Remove unwanted frequencies before distortion
   - Prevents frequency masking issues

3. **Distortion Third**: Apply harmonic saturation to shaped signal
   - Distortion after EQ creates more controlled harmonic content
   - Prevents muddy low-end distortion

4. **Modulation Fourth**: Modulate the tonally shaped, saturated signal
   - Chorus/flanger on distorted guitar sounds natural
   - Modulation before reverb creates cleaner effect

5. **Pitch Fifth**: Pitch shifting after tone shaping
   - Harmonizers work better on EQ'd and compressed signals
   - Prevents artifacts from pitch shifting raw signals

6. **Delay Sixth**: Time-based effects on fully processed signal
   - Delays repeat the complete processed sound
   - Prevents delay feedback from coloring tone

7. **Reverb Seventh**: Spatial ambience as final creative element
   - Reverb encompasses all processing
   - Creates natural sense of space

8. **Spatial Eighth**: Final stereo imaging adjustments
   - Width/panning after all processing
   - Prevents phase issues with earlier effects

9. **Utility Last**: Final gain/DC correction
   - Master output control
   - Safety net for unexpected level issues

    RETURN FALSE

### 6. HARDWARE CONTROL INTERFACE

#### 6.1 Hardware Components

**3 Rotary Encoders (EC11 style):**
- Type: Incremental quadrature encoders
- Resolution: 20 detents per revolution
- Integrated push buttons
- Pin configuration per encoder:
  - A pin (quadrature phase A)
  - B pin (quadrature phase B)
  - Button pin (active low with pull-up)

**Pin Assignments**:
```
Encoder 1 (E1): GPIO 5 (A), GPIO 6 (B), GPIO 26 (Button)
Encoder 2 (E2): GPIO 23 (A), GPIO 24 (B), GPIO 25 (Button)
Encoder 3 (E3): GPIO 17 (A), GPIO 27 (B), GPIO 22 (Button)
```

**3 Three-Way Switches:**
- Type: SPDT ON-OFF-ON toggle switches
- Positions: UP / MIDDLE / DOWN
- Two GPIO pins per switch decode 3 positions

**Pin Assignments**:
```
Switch 1 (SW1): GPIO 19, GPIO 21 (Mode: PRESET/MIX/AI)
Switch 2 (SW2): GPIO 16, GPIO 20 (Bank: A/B/MORPH)
Switch 3 (SW3): GPIO 12, GPIO 13 (Bypass: TRUE_BYPASS/PROCESS/KILL_DRY)
```

#### 6.2 GPIO Polling Architecture

```
CLASS HardwareController:

    THREAD pollingThread:

        FUNCTION run():
            WHILE running:
                // Poll at 1000 Hz (1ms intervals)
                SLEEP(0.001)

                // Read encoder states
                FOR EACH encoder IN [E1, E2, E3]:
                    currentA = readGPIO(encoder.pinA)
                    currentB = readGPIO(encoder.pinB)
                    currentButton = readGPIO(encoder.pinButton)

                    // Quadrature decoding
                    IF currentA != encoder.lastA:
                        IF currentB != currentA:
                            encoder.position++  // Clockwise
                            postEvent(ENCODER_TURN, encoder.id, +1)
                        ELSE:
                            encoder.position--  // Counter-clockwise
                            postEvent(ENCODER_TURN, encoder.id, -1)

                        encoder.lastA = currentA

                    // Button detection with debouncing
                    IF currentButton != encoder.lastButton:
                        debounceTimer = getCurrentTime()
                        IF (debounceTimer - encoder.lastButtonTime) > 10ms:
                            IF currentButton == LOW:  // Button pressed
                                postEvent(ENCODER_PRESS, encoder.id)

                            encoder.lastButton = currentButton
                            encoder.lastButtonTime = debounceTimer

                // Read switch states
                FOR EACH switch IN [SW1, SW2, SW3]:
                    pin1 = readGPIO(switch.pin1)
                    pin2 = readGPIO(switch.pin2)

                    // Decode 3-position switch
                    IF pin1 == HIGH AND pin2 == LOW:
                        position = UP
                    ELSE IF pin1 == LOW AND pin2 == LOW:
                        position = MIDDLE
                    ELSE IF pin1 == LOW AND pin2 == HIGH:
                        position = DOWN

                    // Detect position changes
                    IF position != switch.lastPosition:
                        debounceTimer = getCurrentTime()
                        IF (debounceTimer - switch.lastChangeTime) > 10ms:
                            postEvent(SWITCH_CHANGE, switch.id, position)
                            switch.lastPosition = position
                            switch.lastChangeTime = debounceTimer

    END THREAD

END CLASS
```

**Key Features**:
- **Thread-safe**: Separate polling thread (1000 Hz) from UI thread (30 Hz)
- **Debouncing**: 10ms debounce for mechanical switch stability
- **Event-driven**: Hardware events posted to thread-safe queue
- **Low latency**: 1ms polling ensures immediate response
- **Atomic operations**: Lock-free accumulators for encoder turns

#### 6.3 Event Bus Architecture

```
CLASS EventBus:

    MEMBERS:
        queue: ThreadSafeQueue<Event>
        subscribers: Map<EventType, List<Callback>>

    FUNCTION postEvent(type, data):
        event = Event(type, data, timestamp)
        queue.push(event)

    FUNCTION subscribe(type, callback):
        subscribers[type].add(callback)

    FUNCTION processEvents():
        // Called from UI thread at 30 Hz
        WHILE NOT queue.empty():
            event = queue.pop()

            FOR EACH callback IN subscribers[event.type]:
                callback(event)

END CLASS
```

**Event Types**:
```
ENCODER_TURN:
    - encoder_id: 0, 1, or 2
    - delta: +1 (CW) or -1 (CCW)
    - timestamp

ENCODER_PRESS:
    - encoder_id: 0, 1, or 2
    - timestamp

SWITCH_CHANGE:
    - switch_id: 0, 1, or 2
    - position: UP, MIDDLE, or DOWN
    - timestamp
```

#### 6.5 Encoder Accumulator System

To handle rate mismatch (1000 Hz polling vs. 30 Hz processing):

```
CLASS PluginProcessor:

    MEMBERS:
        encoderAccum: Atomic<float>[3] = {0.0, 0.0, 0.0}

    FUNCTION handleEncoderEvent(encoderID, delta):
        // Called from hardware thread at 1000 Hz
        // Accumulate turns atomically
        encoderAccum[encoderID].fetch_add(delta)

    FUNCTION processGPIOEvents():
        // Called from UI thread at 30 Hz

        FOR i = 0 TO 2:
            // Drain accumulator
            accumulatedDelta = encoderAccum[i].exchange(0.0)

            IF accumulatedDelta != 0.0:
                behavior = getEncoderBehavior(i, currentMode)

                // Discrete parameters: limit to ±1 step per frame
                IF behavior.parameterType == DISCRETE:
                    step = (accumulatedDelta > 0) ? +1.0 : -1.0
                    updateParameter(behavior.parameterID, step)

                // Continuous parameters: apply full delta
                ELSE:
                    updateParameter(behavior.parameterID, accumulatedDelta)

END CLASS
```

**Benefits**:
- Prevents preset stepping jumps (was jumping 1→10 with direct processing)
- Smooth continuous parameter changes
- Thread-safe without locks (atomic operations)
- Rate adaptation (1000 Hz → 30 Hz)

### 7. A/B COMPARISON SYSTEM

#### 7.1 Architecture

```
CLASS ABStateEngine:

    MEMBERS:
        bankA: ParameterBank
        bankB: ParameterBank
        activeBank: BankID (A or B)

    STRUCT ParameterBank:
        input_gain: float
        mix_wetdry: float
        output_level: float
        macro_warmth: float
        macro_size: float
        macro_punch: float
        // Can be extended to include all effect parameters

    FUNCTION switchToBank(targetBank):
        IF targetBank == activeBank:
            RETURN  // Already on this bank

        // Capture current bank parameters from APVTS
        currentBank = (activeBank == BANK_A) ? bankA : bankB
        currentBank.input_gain = inputParam.get()
        currentBank.mix_wetdry = mixParam.get()
        currentBank.output_level = outputParam.get()
        currentBank.macro_warmth = warmthParam.get()
        currentBank.macro_size = sizeParam.get()
        currentBank.macro_punch = punchParam.get()

        // Switch active bank
        activeBank = targetBank

        // Apply new bank parameters to APVTS
        newBank = (activeBank == BANK_A) ? bankA : bankB
        inputParam.setValueNotifyingHost(newBank.input_gain)
        mixParam.setValueNotifyingHost(newBank.mix_wetdry)
        outputParam.setValueNotifyingHost(newBank.output_level)
        warmthParam.setValueNotifyingHost(newBank.macro_warmth)
        sizeParam.setValueNotifyingHost(newBank.macro_size)
        punchParam.setValueNotifyingHost(newBank.macro_punch)

    FUNCTION getActiveBank():
        RETURN (activeBank == BANK_A) ? bankA : bankB

END CLASS
```

#### 7.2 Switching Workflow

```
USER: Loads preset in Bank A
    ↓
SYSTEM: Stores all parameters in bankA structure
    ↓
USER: Adjusts parameters (E2 for mix, E3 for output, etc.)
    ↓
SYSTEM: Parameters update in real-time, stored in bankA
    ↓
USER: Flips SW2 to Bank B position
    ↓
SYSTEM:
    1. Captures current bankA parameters from APVTS
    2. Switches activeBank pointer to BANK_B
    3. Applies bankB parameters to APVTS
    ↓
AUDIO: Immediate switch to Bank B sound
    ↓
USER: Adjusts parameters for Bank B
    ↓
SYSTEM: Parameters update in Bank B only
    ↓
USER: Flips SW2 back to Bank A
    ↓
SYSTEM: Instantly restores Bank A parameters
    ↓
AUDIO: Immediate return to Bank A sound
    ↓
USER: Can rapidly toggle SW2 for A/B comparison
```

**Key Features**:
- **Independent Storage**: Each bank maintains complete parameter state
- **Instant Switching**: Hardware switch provides <1ms switching time
- **Parameter Isolation**: Changes to Bank A don't affect Bank B and vice versa
- **Debouncing**: 10ms debounce prevents mechanical switch bounce
- **Capture-Switch-Apply**: Three-step workflow prevents stale parameter values

**Processing Algorithm**:

```
FUNCTION processBlock(audioBuffer):

    // Apply input gain
    audioBuffer.applyGain(inputGainValue)

    // Create dry signal copy for mix
    drySignal = audioBuffer.clone()

    // Process through active slots
    FOR EACH slot IN [slot1, slot2, slot3, slot4, slot5, slot6]:
        IF slot.bypass == FALSE AND slot.engine != NULL:
            slot.engine.process(audioBuffer)

    // Mix wet/dry
    wetDryMix = mixWetDryValue  // 0.0 = dry, 1.0 = wet
    FOR channel = 0 TO numChannels:
        FOR sample = 0 TO numSamples:
            audioBuffer[channel][sample] =
                (drySignal[channel][sample] * (1.0 - wetDryMix)) +
                (audioBuffer[channel][sample] * wetDryMix)

    // Apply output level
    audioBuffer.applyGain(outputLevelValue)

END FUNCTION
```
